# Bybit Grid Bot

Сканер волатильных USDT-перпетуалов на Bybit и автоматическая нейтральная сетка.

## Деплой на Railway через GitHub

1. Создай **приватный** репозиторий на GitHub и загрузи туда все файлы этой папки
   (кнопка *Add file → Upload files*). Файл `.env` с ключами в репозиторий **не** клади.
2. На railway.com: *New Project → Deploy from GitHub repo* → выбери репозиторий.
3. В сервисе открой **Variables** и добавь:

| Переменная | Значение |
|---|---|
| `BYBIT_API_KEY` | ключ API |
| `BYBIT_API_SECRET` | секрет API |
| `BOT_ARGS` | параметры бота, например `--budget 30 --leverage 3 --tp-usdt 1` |
| `CONTROL_KEY` | (рекомендуется) пароль для кнопок «Старт/Стоп» на странице, иначе их может нажать любой, у кого есть ссылка |
| `START_PAUSED` | `1` — после перезапуска бот ждёт нажатия «Старт» |
| `HTTPS_PROXY` | (если Bybit блокирует IP Railway) `socks5://user:pass@host:port` или `http://…` |

4. **Settings → Networking → Generate Domain**: появится ссылка на страницу бота
   (состояние, баланс, текущая сетка, скан, закрытые сетки, лог). Ошибки настройки тоже видны там.

Бот сразу торгует на **реальном счёте**. Для учебного счёта добавь `--testnet` в `BOT_ARGS`
(или переменную `BYBIT_ENV=testnet`) и ключи с testnet.bybit.com.

## Параметры (BOT_ARGS)

| Флаг | По умолчанию | Что делает |
|---|---|---|
| `--testnet` | выкл | учебный счёт вместо реального |
| `--dry` | выкл | только показывать план, без ордеров |
| `--budget` | 50 | маржа на одну сетку, USDT |
| `--leverage` | 3 | плечо |
| `--max-levels` | 20 | макс. уровней сетки |
| `--tp-usdt` | 0 | закрыть при прибыли ≥ X$ |
| `--max-loss` | 30 | закрыть при убытке ≥ X% маржи (0 = выкл) |
| `--max-minutes` | 60 | макс. жизнь сетки |
| `--shift-steps` | 1 | сетка идёт за ценой, когда цена дальше края на N шагов |
| `--shift-sec` | 0 | сколько секунд цена должна быть за краем до сдвига |
| `--chase-sec` | 1.5 | закрытие: через сколько секунд переставлять лимитку к новой цене |
| `--chase-tries` | 5 | закрытие: мейкер-попыток, потом быстрая лимитка через спред |
| `--chase-slip` | 5 | быстрая лимитка: не дальше N тиков от лучшей цены |
| `--poll` | 1 | как часто проверять исполнения, сек |
| `--exit-er` | 0 | закрыть при тренде (ER выше значения), 0 = выкл |
| `--min-1m` | 0.5 | мин. размах за минуту для входа, % |
| `--max-er` | 0.5 | макс. трендовость для входа |
| `--min-vol` | 10000000 | мин. оборот 24ч, USDT |

## Как работает сетка

- Buy-лимитки ниже цены, Sell выше. После исполнения сразу ставится встречная лимитка на соседний уровень.
- Цена ушла за край сетки → сетка той же ширины перестраивается вокруг цены. Позиция не растёт больше маржи × плечо.
- **Маркет-ордеров нет.** Закрытие: лимитка у лучшей цены, перестановка каждые `--chase-sec` сек,
  после `--chase-tries` попыток — быстрая лимитка через спред (IOC) с ограничением цены.

## Важно

- Аккаунт Bybit: Unified. Режим позиций One-Way или Hedge — бот определяет сам.
- API-ключ: только право торговли деривативами, без вывода. Привязку к IP ставь только
  если у тебя статический IP (прокси или платный static IP Railway).
- При редеплое/остановке Railway шлёт SIGTERM — бот снимает ордера и закрывает позицию лимитками.
  Чтобы у него было время на догон, добавь переменную `RAILWAY_DEPLOYMENT_DRAINING_SECONDS=30`.
- Держи `numReplicas` = 1, иначе две копии будут торговать одновременно.
- В Railway → Settings выключи Serverless / App Sleeping.
- Если на том же счёте Bybit работает другой бот (например grid-grok), бот пропускает монеты,
  где уже есть позиция или открытые ордера. Надёжнее дать ему отдельный субаккаунт и ключ.

## Локальный запуск

```
pip install -r requirements.txt
python bybit_grid_bot.py --dry
```

## Нейросеть

Встроенная нейросеть (MLP на numpy) учится предсказывать доходность сетки в % от объёма позиции за 60 мин:

- **Учебные сетки:** раз в час бот берёт последние 1000 минутных свечей ~30 ликвидных монет и прогоняет
  на них свою сетку по тем же правилам (сдвиг за ценой, лимит позиции, стоп по убытку, комиссии) — тысячи примеров.
- **Реальные сетки:** каждая закрытая сетка на бирже добавляется в обучение с весом ×3.
- **Решения:** для каждого кандидата сеть сравнивает 3 шага сетки (частый / обычный / редкий), берёт лучший
  и пропускает монеты с прогнозом ниже `--nn-min-edge`.
- **Проверка:** последние 20% данных не участвуют в обучении. Сеть принимает решения, только если отобранные ею
  сетки там в плюсе и лучше всех сеток сканера; иначе бот работает по сканеру, а сеть продолжает учиться.
- **Графики** на странице бота: ошибка по эпохам, качество на проверке по обучениям, объём данных, прогнозы.
- **Мысли нейросети** на странице: что собрала и какой шаг сетки лучше шёл на свежем рынке, итоги каждого обучения
  (ошибка, проверка, сравнение с прошлым разом, заучивание прошлого), почему включилась или нет, прогнозы по каждой монете
  для частой/обычной/редкой сетки и три главных фактора прогноза, разбор каждой реальной сетки (прогноз vs итог) и план.

Данные и модель хранятся в `NN_PATH` (по умолчанию `/data/nn`, если подключён Volume в `/data`).
Флаги: `--no-nn` (сеть учится, но не решает), `--nn-min-edge 0.02`, `--nn-symbols 30`, `--nn-refresh 60`,
`--nn-epochs 60`.
