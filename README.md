# Bybit Grid Bot

Сканер волатильных USDT-перпетуалов на Bybit и автоматическая нейтральная сетка.

## Деплой на Railway через GitHub

1. Создай **приватный** репозиторий на GitHub и загрузи туда все файлы этой папки
   (кнопка *Add file → Upload files*). Файл `.env` с ключами в репозиторий **не** клади.
2. На railway.com: *New Project → Deploy from GitHub repo* → выбери репозиторий.
3. В сервисе открой **Variables** и добавь:

| Переменная | Значение |
|---|---|
| `BYBIT_API_KEY` | ключ API |
| `BYBIT_API_SECRET` | секрет API |
| `BOT_ARGS` | параметры бота, например `--budget 30 --leverage 3 --tp-usdt 1` |
| `CONTROL_KEY` | (рекомендуется) пароль для кнопок «Старт/Стоп» на странице, иначе их может нажать любой, у кого есть ссылка |
| `START_PAUSED` | `1` — после перезапуска бот ждёт нажатия «Старт» |
| `HTTPS_PROXY` | (если Bybit блокирует IP Railway) `socks5://user:pass@host:port` или `http://…` |

4. **Settings → Networking → Generate Domain**: появится ссылка на страницу бота
   (состояние, баланс, текущая сетка, скан, закрытые сетки, лог). Ошибки настройки тоже видны там.

Бот сразу торгует на **реальном счёте**. Для учебного счёта добавь `--testnet` в `BOT_ARGS`
(или переменную `BYBIT_ENV=testnet`) и ключи с testnet.bybit.com.

## Параметры (BOT_ARGS)

| Флаг | По умолчанию | Что делает |
|---|---|---|
| `--testnet` | выкл | учебный счёт вместо реального |
| `--dry` | выкл | только показывать план, без ордеров |
| `--budget` | 50 | маржа на одну сетку, USDT |
| `--leverage` | 3 | плечо |
| `--max-levels` | 20 | макс. уровней сетки |
| `--tp-usdt` | 0 | закрыть при прибыли ≥ X$ |
| `--max-loss` | 30 | закрыть при убытке ≥ X% маржи (0 = выкл) |
| `--max-minutes` | 60 | макс. жизнь сетки |
| `--shift-steps` | 1 | сетка идёт за ценой, когда цена дальше края на N шагов |
| `--shift-sec` | 0 | сколько секунд цена должна быть за краем до сдвига |
| `--chase-sec` | 1.5 | закрытие: через сколько секунд переставлять лимитку к новой цене |
| `--chase-tries` | 5 | закрытие: мейкер-попыток, потом быстрая лимитка через спред |
| `--chase-slip` | 5 | быстрая лимитка: не дальше N тиков от лучшей цены |
| `--poll` | 1 | как часто проверять исполнения, сек |
| `--exit-er` | 0 | закрыть при тренде (ER выше значения), 0 = выкл |
| `--min-1m` | 0.5 | мин. размах за минуту для входа, % |
| `--max-er` | 0.5 | макс. трендовость для входа |
| `--min-vol` | 10000000 | мин. оборот 24ч, USDT |
| `--max-24h` | 60 | анти-памп: не торговать монету, если за 24ч цена изменилась больше чем на ±X% (0 = выкл) |
| `--max-move` | 4 | анти-памп: не открывать сетку, если за окно сканера (15 мин) цена уже ушла больше чем на ±X% |
| `--trend-shifts` | 3 | закрыть сетку, когда ей нужен 4-й сдвиг подряд в одну сторону (памп/тренд), 0 = выкл |
| `--budget-pct` | 25 | маржа на одну сетку в % от баланса; если > 0 — главнее `--budget` (0 = брать `--budget` в $) |
| `--max-loss-pct-bal` | 4.5 | потолок убытка на сетку в % от баланса; если > 0 — главнее `--max-loss-usdt` |
| `--day-loss-pct-bal` | 8 | дневной лимит в % от баланса на начало суток UTC; если > 0 — главнее `--day-loss-usdt` |
| `--max-loss-usdt` | 4 | жёсткий потолок убытка на одну сетку в $, поверх `--max-loss` и стопа нейросети (0 = выкл) |
| `--day-loss-usdt` | 15 | закрытые сетки за сутки UTC дали минус ≥ X$ — новых сеток до следующих суток нет (0 = выкл) |

## Как работает сетка

- Buy-лимитки ниже цены, Sell выше. После исполнения сразу ставится встречная лимитка на соседний уровень.
- Цена ушла за край сетки → сетка той же ширины перестраивается вокруг цены. Позиция не растёт больше маржи × плечо.
- Защита от пампов: монеты с большим движением за 24ч и за последние 15 мин не берутся (действует и когда решает
  нейросеть). Если сетка идёт за ценой рывками в одну сторону больше `--trend-shifts` раз подряд — она закрывается,
  а не набирает позицию против движения дальше. Стоп и выход по пампу закрываются сразу быстрой лимиткой через спред.
- **Маркет-ордеров нет.** Закрытие: лимитка у лучшей цены, перестановка каждые `--chase-sec` сек,
  после `--chase-tries` попыток — быстрая лимитка через спред (IOC) с ограничением цены.

## Важно

- Аккаунт Bybit: Unified. Режим позиций One-Way или Hedge — бот определяет сам.
- API-ключ: только право торговли деривативами, без вывода. Привязку к IP ставь только
  если у тебя статический IP (прокси или платный static IP Railway).
- При редеплое/остановке Railway шлёт SIGTERM — бот снимает ордера и закрывает позицию лимитками.
  Чтобы у него было время на догон, добавь переменную `RAILWAY_DEPLOYMENT_DRAINING_SECONDS=30`.
- Держи `numReplicas` = 1, иначе две копии будут торговать одновременно.
- В Railway → Settings выключи Serverless / App Sleeping.
- Если на том же счёте Bybit работает другой бот (например grid-grok), бот пропускает монеты,
  где уже есть позиция или открытые ордера. Надёжнее дать ему отдельный субаккаунт и ключ.

## Локальный запуск

```
pip install -r requirements.txt
python bybit_grid_bot.py --dry
```

## Нейросеть (учится на ходу)

Встроенная нейросеть (MLP на numpy) предсказывает доходность сетки в % от объёма позиции и настраивает сетку.
Это скальпинг, поэтому старая история не используется — только то, что происходит на рынке сейчас:

- **Память:** только последние 4 часа минутных свечей (`--nn-window-hours`). Свежие минуты важнее:
  вес примера вдвое меньше каждые 60 минут (`--nn-half-life-min`).
- **Каждую минуту** бот дочитывает новые свечи по 40 монетам — сначала те, что сейчас дал сканер, потом самые
  ликвидные — и создаёт новый «момент рынка» по каждой. В момент нейросеть сразу фиксирует свой выбор настроек
  (до того, как известен итог), а бот прогоняет по последующим свечам её выбор, обычные настройки и 3 случайные
  комбинации — тем же симулятором, что совпадает с настоящей сеткой бота.
- **Итог** сетки известен, когда она отработает: короткой — через 20 мин, длинной — через 90. Как только итог
  известен, он идёт в обучение. Дообучение — каждую минуту; полное переобучение с нуля — раз в 30 минут
  (`--nn-full-every`), с ранней остановкой.
- **Реальные сетки** на бирже учат её сразу, с весом ×3.
- **Чем управляет нейросеть, когда решает она:**
  - **монетами:** сканер пропускает больше монет (размах за минуту от `--min-1m × 0.5`, трендовость до 0.9 —
    `--nn-scan-relax`, `--nn-scan-max-er`), сеть сама выбирает лучшую и пропускает те, где ждёт минус
    (`--nn-min-edge`);
  - **всеми настройками сетки** — 12 960 комбинаций на каждую монету: частота (4 варианта шага), ширина
    ×0.7/×1/×1.5, обычная или **геометрическая**, лот равный или растущий от цены ×1.2/×1.5, сдвиг за ценой через
    1/2/4 шага, стоп 3/6/10% объёма, **тейк-профит** нет/0.3/0.6/1% объёма, время 10/20/40/60/90 мин
    (`--nn-max-hold`). Если настройки не влезают в минимальный лот биржи — ставятся обычные;
  - **маржой:** от ×0.25 до ×2 от `--budget` по силе прогноза (`--nn-size-min`, `--nn-size-max`);
  - **работающей сеткой:** раз в минуту переоценивает её по текущему рынку; если 3 минуты подряд даже лучшие
    настройки дают дальше минус больше 0.05% объёма — закрывает досрочно лимитками
    (`--nn-exit-edge`, `--nn-exit-confirm`, `--nn-exit-min-age`). Монета работающей сетки учится первой.
  Плечо остаётся за тобой (`--leverage`): на доходность в % оно не влияет, только на риск ликвидации.
- **Быстрая обратная связь:** итог выбора сети попадает в онлайн-проверку, как только её сетка отработала —
  10-минутная через 10 минут. После смены рынка первый час она дообучается вдвое быстрее.
- **Онлайн-проверка:** решения принимает, только если за последние 60 минут (`--nn-eval-min`) её выбор по факту
  в плюсе и лучше обычных настроек в тех же моментах (минимум 20 сделок). Пока проверки мало — решает
  проверка на самом свежем куске при полном переобучении.
- **Детектор смены рынка:** каждую минуту по всем монетам в учёбе (медиана — чтобы тревогу поднимала смена всего
  рынка, а не всплеск одной монеты) сравнивает волатильность последних 15 мин с часом перед ними (порог ×1.7 или
  ÷1.7, `--nn-regime-vol`) и трендовость последних 30 мин с часом перед ними (±0.3, `--nn-regime-er`). Сигнал
  должен держаться 3 минуты (`--nn-regime-confirm`). Если рынок сменился — сеть сразу отдаёт решения обычным
  настройкам, учит новый режим с весом ×3 (`--nn-regime-boost`), переобучается полностью на 300 его примерах и
  возвращается, только набрав 20 итогов своих решений в новом режиме (`--nn-regime-min-n`, не дольше 120 мин —
  `--nn-regime-max`). Онлайн-проверка после этого считается только по новому режиму. Пока итогов обычных
  настроек в новом режиме нет (их сетка 60 мин), сети достаточно быть в плюсе — но маржа тогда не больше ×1;
  как только они появятся, сеть должна быть и лучше их.
  На тесте с 40 монетами: ложных тревог за 3 часа — 0, настоящая смена поймана через 9 минут.
- **Страница:** онлайн-проверка (выбор сети vs обычные), ошибка прогноза на ещё не виденных сетках, полное
  переобучение по эпохам, память, режим рынка, план, на что опирается, прогнозы по кандидатам и журнал мыслей
  («Учусь на ходу» раз в 10 минут).

Модель и данные — в `NN_PATH` (по умолчанию `/data/nn`, если подключён Volume в `/data`). Кэш старой истории
удаляется автоматически. Флаги: `--no-nn` (учится, но не решает), `--nn-symbols 40`, `--nn-window-hours 4`,
`--nn-stride 1`, `--nn-half-life-min 60`, `--nn-full-every 30`, `--nn-online-epochs 2`, `--nn-eval-min 60`,
`--nn-eval-min-n 20`, `--nn-max-hold 90`, `--nn-configs 3`, `--nn-min-edge 0.02`, `--nn-size-min 0.25`,
`--nn-size-max 2`.
